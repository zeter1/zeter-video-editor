# История изменений Zeter Video Editor

Все значимые изменения видеоредактора фиксируются здесь **под конкретной версией**, начиная с самых новых. Записи ориентированы на пользователей и сопровождаются техническими подробностями, когда это необходимо.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/) и [Semantic Versioning 2.0](https://semver.org/spec/v2.0.0.html). [Правила ведения и выпуска версий](docs/CHANGELOG_GUIDE.md).

> Версия исходного кода или тестовой сборки **не равнозначна опубликованному релизу**. Статус выпуска указан в каждом разделе. GitHub Actions DEBUG/NSIS artifact — не подписанный публичный выпуск.

## [0.1.0-alpha.1] — 2026-10-11

> **Предварительная версия для разработки и проверок (не выпущена публично).** Эта запись описывает изменения в ветке версии; установка и автообновление не выполнялись.

### Исправлено
- **Короткий scrub не разрешает устаревшему кадру двигать курсор (Stage C, draft #44).** Даже если ручная перемотка в пределах 120 мс не вызывает native `seeking`, новое внешнее значение playhead сбрасывает trusted compositor-frame anchor; обычные собственные `onSeek` из preview его сохраняют. Добавлен React regression: 20 мс scrub и поздний 4.8s frame не должны прыгать вперёд. Требуется exact-head Windows CI и Windows WebView2 QA; Rust/.vcut/media/export неизменны.
- **Восстановление предпросмотра после пропущенных WebView2 callbacks (Stage C, draft #44).** После подтверждённого кадра в непрерывном Play рост счётчика `presentedFrames` позволяет догнать реальные кадры при пропуске более 120 мс видео. При перемотке, паузе и смене клипа доверенный якорь сбрасывается, старые кадры не могут переносить playhead. Добавлены unit-тесты для 2× и React-тест на пропуск/seek. Windows CI и ручная WebView2 QA ещё необходимы; .vcut v2, экспорт, исходные медиа и версия не изменены.
- **Запоздавшее native `ended` после перемотки не переносит курсор в конец (Stage C, draft #44).** Конец видео принимается только когда оба времени — текущая позиция декодера и playhead — находятся в пределах 120 мс времени монтажа от фактической границы клипа, и включено Play. Добавлены unit и React-тесты для задержанного/настоящего/повторного сигнала и отсутствия Rust onCommit. Исходные файлы, .vcut v2, экспорт и номер версии не меняются; новый exact-head CI и ручной Windows QA ждут подтверждения.
- **Старый кадр после перемотки назад не сдвигает курсор вперёд (Stage C, draft #44).** Предпросмотр с `requestVideoFrameCallback` отклоняет кадры, опережающие запрошенный playhead более чем на 120 мс времени монтажа (с пересчётом скорости), даже если `mediaTime` и `currentTime` согласованы друг с другом. Ранее отложенный кадр с прежней поздней позиции мог ложно передвинуть курсор после scrub назад. Добавлены unit тесты для 1×/2× и React-тест реальной смены playhead и отложенного callback; Rust `onCommit` не вызывается. Исходные медиа, .vcut v2, экспорт и версия не менялись; ручная Windows GUI/speaker QA пока не подтверждена.
- **Видеодекодер на 2× больше не делает лишние seek (Stage C, DRAFT #44).** В `PreviewPlayer.tsx` допустимое отклонение native `currentTime` теперь масштабируется скоростью клипа в исходных секундах: при Play 120 мс **timeline**, при Pause 1 мс **timeline**. Раньше фиксированные 120/1 мс source вызывали лишние перемотки и возможные остановки звука на 2×. Новый React/Vitest тест на `source_in=1s` проверяет 150 мс source без seek, 260 мс source с seek и точный paused stepping, а также отсутствие Rust `onCommit`. Исходные медиа, .vcut v2, экспорт и версия 0.1.0-alpha.1 не меняются; exact-head Windows CI и ручной GUI/speaker QA требуют подтверждения.
- **Ускоренные аудиоклипы: устранены лишние seek/pause (Stage C, draft #44).** Допуск отклонения native Audio clock теперь приведён к времени монтажа с учётом clip.speed: 120 мс на timeline при Play и 1 мс при Pause, аналогично Video. На 2× source drift 150 мс (75 мс timeline) не приводит к повторному seek; 260 мс (130 мс timeline) приводит к seek с ожиданием native seeked. Добавлен React/Vitest regression; исходные медиа, экспорт, .vcut v2, версия 0.1.0-alpha.1 неизменны. CI exact HEAD и ручная Windows GUI/speaker QA требуют подтверждения.
- **Звук при перемотке внутри того же видео (Stage C, DRAFT #44):** при live scrub с 1.1 до 1.4 с нативный WebView2 `video.currentTime` мог немедленно показать 4.4 с (клип с `source_in=4 с`), хотя последний отправленный композитору кадр был 4.1 с. Прежний audio gate запоминал только идентификатор клипа и мог снова разблокировать отдельную WAV/MP3 дорожку без нового кадра. Теперь `PreviewPlayer.tsx` дополнительно сохраняет последний подтверждённый `metadata.mediaTime` в микросекундах и разрешает звук только если подтверждённый кадр совпадает с текущим playhead в пределах 120 мс. При Pause/Stop подтверждение сбрасывается; старый WebView2 без `requestVideoFrameCallback` продолжает использовать legacy decoder/seeked fallback. `PreviewTransportIntegration.test.tsx` проверяет in-clip scrub, преждевременный `seeked` Audio, устаревший кадр, новый кадр и отсутствие Rust commit. Изменение не затрагивает исходные медиа, формат `.vcut` v2, экспорт и номер `0.1.0-alpha.1`; это не sample-accurate mix, native Windows GUI/speaker QA не выполнен. Результат exact-HEAD CI для нового commit требует отдельной проверки.
- **Presented-frame WebView2 preview clock (#44, Stage C DRAFT):** вместо опережающего реальные пиксели decoder `HTMLVideoElement.currentTime` предварительный просмотр в WebView2 с поддержкой `requestVideoFrameCallback` использует `metadata.mediaTime` кадра, отправленного в compositor. Кадры со старого seek, до `source_in`, с несоответствующим native decoder clock и нечисловым временем не двигают playhead и не разрешают независимый Audio; собственно событие `playing`/`seeked` теперь недостаточно для старта Audio при наличии frame API. При Stop/Pause/смене клипа callback отменяется; в старых WebView2 сохраняется прежний rAF/currentTime fallback, на still/gap — bounded rAF. `previewTransport.test.ts` тестирует 2x/trim/scrub, `PreviewTransportIntegration.test.tsx` — compositor-frame gate, Audio, Stop и отсутствие `onCommit`. Требуются terminal exact-HEAD Windows CI и ручной Windows video/speaker QA; это не sample-accurate A/V mixer и не Direct/Proxy/Composite/export parity. Исходные медиа, Rust project/.vcut v2 и версия 0.1.0-alpha.1 не менялись.
- **Обработка прерываний native Play (#44, Stage C DRAFT):** `AbortError` от `HTMLMediaElement.play()` при перемотке, паузе или загрузке больше не показывается как ошибка кодека для видео/отдельного Audio. Настоящий `NotSupportedError` по-прежнему вызывает сообщение, а удачный перезапуск звука очищает старую ошибку. Добавлены React/Vitest-тесты, проверяющие реальные ошибки и неизменность Rust проекта. Ни исходные медиа, ни экспорт, ни `.vcut` v2, ни версия `0.1.0-alpha.1` не менялись. Требуется exact-HEAD Windows CI и ручная GUI/speaker QA.
- **Безопасный повторный seek A/V при перемещении playhead во время Play (#44, Stage C DRAFT):** исправлена гонка, при которой совпавшее сразу после присваивания `audio.currentTime` значение ошибочно принималось за завершённый native seek и отдельная Audio-дорожка могла запускаться до `seeked`. В `PreviewAudioTracks.tsx` введено подтверждение ожидающего seek через native событие; `PreviewPlayer.tsx` перед разрешением standalone Audio проверяет текущие видеочасы прямо на новом playhead (не только ранее выставленный флаг готовности). Реальный Windows CI на предыдущем SHA `dabca8d` выявил три Vitest failure (незавершённый seek, устаревшие ожидания); интеграционные тесты дополнены live-scrub regression, ожидания тестов приведены к корректному asynchronous seek protocol. Новая exact-HEAD Windows CI ещё требует terminal подтверждения; sample-accurate mixer, ручной Windows speaker QA и Direct/Proxy/Composite/export parity не заявлены. Rust snapshot, исходники, .vcut v2, экспорт и версия 0.1.0-alpha.1 не менялись.
- **Ожидание исходного seek на отдельной аудиодорожке (#44 Stage C DRAFT):** до исправления native HTMLAudioElement мог запустить WAV/MP3 с нулевой позиции до окончания перемотки к `source_in` при начале клипа или смене playhead. `PreviewAudioTracks.tsx` теперь запускает звук только после metadata и подтверждённого seeked с совпадающим audio-clock; несоответствующее событие не выпускает звук, последующий seek снова ставит дорожку на паузу. Тесты: Vitest source_in 1s / 2x / просроченный seeked, обновлён React preview integration; CI нового exact SHA ожидает проверки. Это не sample-accurate mixer, ручной Windows GUI/speaker QA не проводился. .vcut v2, исходные медиа, экспорт и версия 0.1.0-alpha.1 не менялись.
- **Целочисленная временная шкала при native video preview (#44, Stage C DRAFT):** устранена реальная CI-регрессия при переходе между соседними видео с `source_in=4 с`: WebView2 отдавал дробную секунду `4.1`, преобразование давало `1 099 999.9999999995` мкс вместо `1 100 000` мкс, из-за чего строгая синхронизация onSeek/React/Vitest не проходила. `previewTransport.ts` теперь округляет вычисленное время до целого микросекундного положения **после** корректировки на source_in и clip.speed и ограничивает концами клипа. Добавлен unit-тест на 4.1 с, 2x и границы. Отдельный настоящий Windows WebView2 E2E `preview-adjacent-sync.spec.ts` проверяет бесшовный стык двух видео (B: source_in 4 с), WAV через монтажный стык, фактический drift video vs audio (< 300 мс при playback), Pause/Restart/Stop и неизменность Rust snapshot. Не является sample-accurate mixer или ручной проверкой на слух. Причина и исходная ошибка: Windows Actions #38158382965 на 2602b966, 1 frontend failure; новый exact-head CI должен завершиться успешно перед любыми утверждениями об исправлении. Схема .vcut v2, исходники, экспорт и версия 0.1.0-alpha.1 не менялись; main не затронут.
- **Синхронизация аудио при переходе между соседними видео (#44, Stage C DRAFT):** раннее native `playing` нового WebView2-декодера могло разблокировать отдельные аудиодорожки до перемотки к `source_in`, поэтому звук начинался поверх не того кадра. Теперь `PreviewPlayer.tsx` проверяет готовность кадра, отсутствие текущего seek и совпадение decoder media-time с ожидаемой позицией в source, а не с зажатым timeline-start, также удерживает video-driven rAF до точного источника и игнорирует поздние события при Pause. Допуск 120 мс задан в единицах timeline и нормализован по `clip.speed`. Новые unit/Vitest React-регрессии проверяют соседние видео с in-point=4 с, отдельное Audio, premature playing, seeked/reclock, 2× и отсутствие Rust `onCommit`. Ограничения: не sample-accurate микшер, Windows ручной GUI/speaker QA ещё не подтверждён; формат .vcut v2, экспорт, исходники и номер 0.1.0-alpha.1 неизменны.
- **Покадровая навигация во время воспроизведения (#44, Stage C DRAFT):** ранее Previous/Next frame меняли playhead, но работающие video/audio/rAF часы могли сразу перезаписать новую позицию; Next также мог перейти за фактический конец монтажа. Теперь `PreviewPlayer.tsx` перед одиночным шагом выключает Play, ограничивает цель интервалом 0..sequencePlayableEndUs и синхронизирует transient clock. Native видео и внешние Audio-дорожки останавливаются через транспортные эффекты. Новые React/Vitest-тесты в `PreviewTransportIntegration.test.tsx` проверяют отмену rAF, границы кадров, паузу video+audio и отсутствие Rust `onCommit`. Нет изменения .vcut v2, экспортного pipeline, Undo/Redo, исходных файлов или номера 0.1.0-alpha.1; Windows ручная проверка и actual decoder frame accuracy ещё не подтверждены.

### Добавлено
- **Управление Stop / возвратом в начало предпросмотра (#44, Stage C DRAFT):** ранее были только Play/Pause, и для повторного просмотра монтажа приходилось вручную возвращать курсор к нулю. Теперь кнопка `Stop` в `PreviewPlayer.tsx` выключает непрерывный transient-транспорт и переводит playhead в 0 мкс; текущие HTMLVideoElement/HTMLAudioElement получают pause через существующую транспортную синхронизацию, и последующий Play стартует с начала. Команда доступна и после паузы, не отправляет Rust `EditCommand`, не увеличивает revision и не меняет .vcut, исходные медиа или экспорт. Два React/Vitest-теста проверяют остановку при проигрывании и при паузе с новым стартом. Добавлен реальный Windows WebView2 E2E с последовательностью `video (source_in=1 с, 2x) → gap с отдельно играющим WAV → image → video (source_in=4 с, 1x)`, окончанием отдельной аудиодорожки и Stop/restart без мутаций Rust; основан на одноразовой копии корректного тестового проекта. **Границы:** клик Stop не является sample-accurate синхронизацией и не подтверждает на слух работу микшера; полный frame-accurate/proxy/composite/export parity и ручной Windows GUI QA остаются впереди. Результат CI следует проверять для финального SHA этого PR, а не переносить с предыдущего `9225c3b`.
- **Отдельные Audio-дорожки в реальном предпросмотре (#44, Stage C DRAFT):** до исправления на таймлайне существовали самостоятельные звуковые клипы, но нажатие Play воспроизводило только звук, встроенный в видео; WAV/MP3 с отдельных дорожек оставались неслышны. Теперь `PreviewAudioTracks.tsx` подключён к `PreviewPlayer.tsx` и запускает собственные HTMLAudioElement для всех активных standalone Audio-клипов через существующий безопасный поток по MediaId. Их position/seek следует общему playhead и учитывает `source_in`, скорость клипа и паузу. Реализованы `SetTrackMute`, mute клипа, объём по `volume`/`gain_db` с безопасным пределом native HTMLMediaElement 0..1, а также fade-in/fade-out по временному положению клипа. Тесты `PreviewAudioTracks.test.tsx` покрывают скорость, source-in, одновременные дорожки, границы, громкость и mute; `e2e/mvp-workflow.spec.ts` проверяет реальное WebView2 воспроизведение WAV, паузу, mute дорожки и отсутствие изменения Rust revision от Play. **Ограничения:** браузерное суммирование без независимого sample-accurate mixer, нет полноценной parity Direct/Proxy/Composite/RenderSnapshot, усиление выше 0 dB ограничивается native volume=1, real-device ручной QA требуется. Экспорт, оригиналы, .vcut v2 и номер разработки `0.1.0-alpha.1` не меняются; изменение пока только в DRAFT PR #44, не в main.\n- **Непрерывный транспорт предпросмотра через изображения и пустые интервалы (#44, stacked DRAFT):** раньше кнопка Play была недоступна в gap/still, а завершение HTML-video останавливало весь предпросмотр независимо от следующих клипов. Теперь `PreviewPlayer.tsx` переключает transient clock между временем декодируемого <video> и ограниченным `requestAnimationFrame` для изображения/пустоты; для видеоклипа учитываются `source_in` и `speed`, пауза/конец привязаны к последнему реальному клипу, а не запасу на UI-шкале. Исправлены шаги по одному кадру в режиме паузы (native seek больше не игнорируется из-за 120-мс допуска), прерванный play() старого клипа не выключает новый. Добавлены `previewTransport.ts`, `previewTransport.test.ts`, `PreviewTransportIntegration.test.tsx` для границ, 2x speed, still/gap/end и отсутствия проектных мутаций. **Ограничение:** это только первый этап Stage C, не полное sample-accurate синхронное A/V смешивание, прокси или композит; требуется exact-HEAD Windows CI и ручной WebView2 QA. Проект, Undo, исходные файлы, export, схема .vcut и номер `0.1.0-alpha.1` не изменены; код пока только в draft PR #44.
- В таймлайне реализована **автопрокрутка вслед за курсором по страницам** (#43): при воспроизведении или переходе на удалённую позицию, если playhead покинул видимую область, шкала смещается так, чтобы его снова было видно. Пока курсор остаётся в окне, пользовательская прокрутка сохраняется; во время drag клипа автосмещение отключено. Код `apps/desktop/src/timeline/followPlayhead.ts`, подключение в `Timeline.tsx`, unit и React-тесты. Это не постоянное Smooth Scroll и не изменение скорости воспроизведения, A/V clock или media source; формат `.vcut` и экспорт неизменны. Функция пока только в stacked draft PR #43, требует exact-head CI и ручной Windows QA.

- В AI workspace добавлен реальный путь **локальных автоматических субтитров** для выбранного видео/аудиоклипа: `TranscriptionRuntimePanel` запускает Tauri `start_transcription` только по явному действию пользователя; Rust `transcription_service.rs` проверяет совместимость и контрольные данные локальной модели, нормализует звук через управляемый FFmpeg, запускает изолированный AI worker и возвращает сегменты для чтения. До кнопки Apply проект не меняется; `apply_transcription` вызывает существующий `ProjectService::apply_transcript_result` со сверкой source revision и обычной отменяемой историей. Путь перенесён выборочно из draft PR #8, сохранены новые Windows-импорт, drag/drop и горячие клавиши PR #40/#41. Нет облачной отправки и изменений `.vcut`; ручные субтитры остаются доступными. Добавлены React-тесты подтверждения/ошибки и Windows WebView2 E2E проверка отказа при неполном импорте модели без изменения проекта. **Ограничения:** реальный запуск whisper.cpp с настоящей моделью и полноценный GUI happy-path на этой ветке ещё НЕ ПРОВЕРЕНЫ; Silence/Highlights production backend всё ещё не подключены, Windows CI нового HEAD ещё требуется.
